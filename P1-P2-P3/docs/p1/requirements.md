# P1 요구사항 문서

## 유저 스토리

### 학생 (STUDENT)
| ID | 스토리 | 수용 기준 (AC) |
|----|--------|---------------|
| US-01 | 학생으로서 강의 목록을 보고 싶다 | 강의 목록이 페이지네이션으로 표시된다 |
| US-02 | 강의 상세 정보를 확인하고 싶다 | 커리큘럼, 가격, 강사 정보가 표시된다 |
| US-03 | 장바구니에 강의를 담고 싶다 | 로그인 후 장바구니 추가 가능, 중복 불가 |
| US-04 | 장바구니에서 결제하고 싶다 | 선택된 강의만 결제, 주문 내역 생성 |
| US-05 | 수강 진도를 관리하고 싶다 | 챕터별 완료 체크, 전체 진도율 계산 |
| US-06 | 강의에 리뷰를 남기고 싶다 | 1~5점, 텍스트 입력, 수정/삭제 가능 |
| US-07 | 강의를 북마크하고 싶다 | 북마크 추가/제거, 마이페이지에서 확인 |

### 강사 (TEACHER)
| ID | 스토리 | 수용 기준 (AC) |
|----|--------|---------------|
| US-10 | 강의를 등록하고 싶다 | 제목/카테고리/가격/커리큘럼 입력 후 저장 |
| US-11 | 강의를 수정하고 싶다 | 본인 강의만 수정 가능 |
| US-12 | 강의를 삭제하고 싶다 | 본인 강의만 삭제 가능 |
| US-13 | 수강생 진도를 확인하고 싶다 | 마이페이지에서 수강생별 진도 확인 |

## MVP 범위

### 포함
- 강의 CRUD (인증 필요)
- 회원가입/로그인 (JWT + Refresh Token)
- 장바구니 + 결제 (단순 상태 변경)
- 수강 진도 관리
- 리뷰 CRUD
- 북마크
- 역할 기반 접근 제어 (STUDENT/TEACHER/ADMIN)

### 제외 (P3 이후)
- 실제 PG사 결제 연동
- 이메일 알림
- 동영상 스트리밍
- 관리자 대시보드

## 마일스톤

| 주차 | 목표 |
|------|------|
| 1~2주 | ERD 설계, 기본 CRUD API, 프론트 와이어프레임 |
| 3~4주 | 프론트 구현, API 연동, 테스트 |
| 5~6주 | JWT 인증, Refresh Token, 역할별 접근 제어 |
| 7~8주 | 보안 강화 (Helmet, Rate Limit), 페이지네이션 |
| 9~10주 | 테스트, CI/CD, Docker, 문서화 |
